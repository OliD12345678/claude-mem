BUILD NOTES

What needs new data or backend changes

Front end reuses the existing /v2 card, audio buttons, nav and avatar components. New: the This week route (replaces /v2/team), a public /r/:token route, and the Discovery category.

1 · Rep card links (new)

  • Table card_links: token hash, rep_id, card_id, sent_by, channel, sent_at, expires_at (7 days), revoked_at.
  • Public GET /r/:token, no login. Serves only that card's text and a short-lived signed URL for the 0:28 clip. Rate-limited, noindex.
  • Expired or revoked token shows the expired screen. A saved commitment survives expiry.
  • Token maps to rep_id, so a future logged-in rep home can show the same card and history.

2 · Sending (new)

  • Rep phone and email on the staff profile.
  • SMS and email provider with delivery webhooks. Fixed, privacy-safe templates: rep first name, link, nothing about the prospect.
  • Link preview (Open Graph tags) is generic: “Your coaching card for this week.”
  • POST /cards/:id/send and a batch “send all remaining” endpoint.

3 · Status events (new)

  • Events: sent, delivered, opened, played (clip reached about 80%), committed.
  • This week reads the latest event per rep per week. All events go to the existing audit log.

4 · Commitments (new)

  • Table commitments: link_id, rep_id, card_id, text, starter_used, submitted_at, edited_at, source (link or app).
  • Server rejects empty or whitespace-only text. Edits keep history.
  • Manager sees who submitted and when.
  • Optional manager note stored on the send, shown on the card only.

5 · Recommended call per rep (new)

  • Score each moment from the last 7 days: impact × matches the rep's focus × clip quality, skipping cards already sent.
  • Return a one-line reason string. The manager can pick a different call from Coach.
  • “Start here” order: most calls, then oldest unsent.

6 · Discovery tracking (proposed)

  • New category beside Objection, Value and Booking in the analysis prompt and the card schema.
  • Per call: tag rep questions about the prospect's situation, goals or concerns that come before the first pitch or fact segment. Store count and timestamps.
  • Suggested target (3) is a studio setting. Label it “Proposed metric” until it has been checked against manual labels on about 50 calls.
  • “This count looks wrong” saves a correction for tuning.

7 · Was the commitment kept? (new)

  • For the rep's next 3 analyzed calls after submitted_at, run a check: commitment text + transcript → kept / not yet / not applicable, with an evidence quote and timestamp.
  • Not applicable (no matching situation) is left out of “X of Y”.
  • The manager can override a result on the call page.

8 · Privacy

  • Rep link copy uses prospect first names only. Health terms are filtered out of rep-facing card text and blocked in all SMS, email and preview text.
  • Commitment text can contain health details, so show it only in logged-in manager views. Never send it in a message.
  • Booking-ask rate per rep per week already exists. Team pulse reuses it.
